# The Unchosen Log

**From the episode:** *Lock-in is a record-keeping failure.*
One page that turns a future migration from archaeology into arithmetic. Nobody
signs a lock-in contract — it accumulates, one convenient default at a time, none
of them written down. This is where they get written down.

## When to use it

At the moment a team takes a vendor's default — the built-in queue, the identity
system, the storage format. One line, written while the decision is fresh. Not a
quarterly exercise; a habit at decision time.

## The practice

**Write down what you did not choose.** Take the default — it is usually the right
call. Then record the alternative you passed on, and why. A recorded trade can be
revisited in an afternoon. An unrecorded one can only be excavated, at consulting
rates, by people who were not in the room.

## The log — one line per default taken

| Date | We took | We did not take | Because | Owner |
|---|---|---|---|---|
| | vendor's managed queue | portable broker, self-run | ships this sprint; ops cost | |
| | | | | |
| | | | | |

**Rules that keep it honest:**
1. One line at decision time beats a paragraph at migration time. Do not let the
   log become a document project — its value is that it is cheap to keep.
2. "Because it was the default" is an acceptable entry. It is still a decision,
   and recording it is the point.
3. The Owner column takes the name of whoever took the default — not to blame,
   but so the future reader knows who to ask. Process, not fault.

## What this buys you

When the pricing changes or the vendor stumbles, your team reads the log and
prices the exit in an afternoon — because every question a migration quote bills
you to answer is already answered, in your own words, one line at a time.
