# The Decision Audit

**From the episode:** *Tokenmaxxing is measuring the input.*
One page for the next AI spend review. Token consumption is an input — spending
more of it is not evidence anything improved, any more than a rising cloud bill
once was. This sheet asks the only question that separates spend from result.

## When to use it

Monthly, or whenever someone presents AI usage numbers as if they were outcomes.
Also before approving an increase in AI budget.

## The practice

**Name one decision that changed.** For each AI initiative, name a specific
decision your organisation made differently — or faster, or with fewer people —
because the tool was there. Not "productivity improved." A decision, with a date
and a name attached. If nobody can name one, the spend is measuring itself.

## The audit — one row per initiative

| | Initiative 1 | Initiative 2 |
|---|---|---|
| What we spend monthly (input) | | |
| One decision that changed because of it | | |
| Who made that decision | | |
| What it would have cost to decide the old way | | |
| If we switched this off tomorrow, who notices first? | | |

**Rules for filling it honestly:**
1. Row two takes a real event — "the pricing review on the 14th used the model's
   summary and finished in one sitting" — never a percentage you cannot trace.
2. "Nobody would notice for a month" in row five is a legitimate answer, and it is
   the most useful sentence this sheet can produce.
3. An initiative with an empty row two for two audits in a row is not failing —
   it is unmeasured. Decide which, deliberately.

## The reframe this protects you from

Usage dashboards reward the wrong instinct: they make *more input* look like
progress. A decision log cannot be gamed that way — either the decision happened
or it did not.
